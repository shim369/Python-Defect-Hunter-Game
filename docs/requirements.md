# 要件定義書: Python-Defect-Hunter-Game

## 1. 目的
KolektorSDD2(KSDD2)の表面欠陥画像を使い、ブラウザで遊べる「欠陥ハンター(人間 vs AI)」を作る。
ポートフォリオとして次を示す。

- 画像・動画の前処理
- PyTorch によるセグメンテーション(小型 U-Net)
- 自前実装の評価指標(IoU / Precision / Recall / F1)
- クラス不均衡への対応
- Docker による再現性

## 2. 前提・制約
| 項目 | 内容 |
|---|---|
| データ | `data/raw/KSDD2/{train,test}/`。`NNNNN.png`(画像)と `NNNNN_GT.png`(マスク)のペア。調査結果は `docs/data_quality.md` |
| ライセンス | CC BY-NC-SA 4.0(非営利)。`data/` は Git に含めない(`.gitignore`) |
| 公開画像 | 数枚のみ。README に出典を明記 |
| 実行環境 | CPU のみ |
| 技術 | Python 3.15.1(uv で固定), PyTorch, OpenCV, FastAPI。フロントは素の HTML + Canvas + JS |
| 実行時 | サーバーでモデルは動かさず、事前生成した予測 PNG を読む |
| コード | 「なぜそうしたか」の短いコメントを入れる(PyTorch 初学者向け) |
| コミット | ユーザーが指示したときのみ |

## 3. ゲーム仕様(機能要件)
### 3.1 必須
- F1. 画像を 1 枚表示する。
- F2. プレイヤーが欠陥と思う場所をマウスでなぞる(Canvas)。
- F3. 「欠陥なし」ボタンを用意する(画像の約 9 割は良品のため)。
- F4. 正解マスクとの IoU で採点する。
- F5. 同じ画像に対する自作モデルの予測と点数を並べて比較表示する。
- F6. 数問ごとに、プレイヤーの Precision / Recall / F1 を表示する。

### 3.2 採点ルール(確定。8 章参照)
- 正解が欠陥あり: プレイヤー塗りと正解マスクの IoU。
- 正解が良品: 「欠陥なし」を選べば満点、何か塗れば 0 点。IoU は 0/0 になるため空マスクの扱いを明示する。
- 画像単位の混同行列(TP/FP/FN/TN)から Precision / Recall / F1 を算出する(画像単位の判定)。

### 3.3 任意
- O1. モデルの判定しきい値スライダー。Precision/Recall のトレードオフを体感できる。
  サーバーでモデルを動かさないため、確率マップ(8bit PNG)を事前生成する。
  **実装:** スライダーは成績画面(5 問ごと・最終)にあり、動かすとサーバー(`POST /api/summary`)が
  そのしきい値で AI の画像単位 P/R/F1 を再計算する。1 問ごとの結果画面の AI 表示は、初期しきい値(0.5)で固定。
  実測では、しきい値を動かすと主に Precision が動き、Recall はほぼ動かない(README 参照)。
- O2. 画面の日本語 / 英語切り替え(右上のスイッチ。文言は `web/static/i18n.json`)。

## 4. ML・データ要件
- 公式の train/test を維持し、train から Val を層化分割する(乱数シード固定)。
- 品質チェックスクリプト: 破損画像、画像とマスクのサイズ不一致、空マスク率、欠陥面積の分布。
- 小型 U-Net。不均衡対応(クラス重み、Dice 損失、Focal 損失など)を設定で切り替え可能にする。
- 各設定の F1・IoU を表で比較し、`configs/` と結果を保存する。
- 評価指標は自前実装(外部ライブラリなし)。torchmetrics 等と突き合わせるテストを書く。
- 境界ケース(空マスク同士、完全一致、完全不一致)を pytest で検証する。
- 予測マスクを PNG として事前生成する。

## 5. 非機能要件
- 再現性: 乱数シード固定。Docker(CPU)で `make train` / `make eval` / `make serve` が同じ結果を出す。
- 軽量性: CPU で学習が現実的な時間に収まる。サーバーは静的配信中心。
- ライセンス遵守: 出典明記、非営利、`data/` 非追跡。
- テスト: pytest(指標、データ処理)。学習・評価コードは短い実データで実際に動かして確認する。

## 8. 決定事項(旧・未確定事項)
- **データ構成・マスク形式:** Phase 0 で確認済み。train 2331 組(欠陥 246)/ test 1004 組(欠陥 110)、マスクは 0/255 の 2 値、画像サイズは不揃い。`train/` に混入した `(copy)` ファイルは読み込みで除外。
- **出題比率:** 実データは約 9:1 だが、そのままだと欠陥画像がほとんど出ず遊べない。
  1 ラウンド 10 問を「欠陥あり 6 : 良品 4」で出題する。
  - 注意: 画面に表示する Precision / Recall / F1 は、この出題比率で算出した値であり、実データ分布での性能ではない。
    実データ分布での AI 指標は、README の結果表(test 全体)で別に示す。
- **1 ラウンドの問題数:** 10 問。
- **成績表示の間隔:** 5 問ごとに中間成績、10 問終了で最終結果(AI との比較付き)。
- **空マスクの IoU:** 正解が良品の場合、「欠陥なし」を選べば 1.0、何か塗れば 0.0 とする。
  正解が欠陥ありで「欠陥なし」を選んだ場合は 0.0。指標の自前実装では、空同士の IoU の扱いを関数の引数で明示し、テストで固定する。
- **AI の初期しきい値(実装時に追加):** 0.5。val で選んだ値(約 0.01)は、val の F1 がしきい値に対してほぼ平坦で偶然に近かったため採用しなかった。
- **公開しない決定:** Vercel などへのデプロイは見送り。データ由来の画像を公開サイトで配る形になり、README の「数枚のみ掲載」の方針と食い違うため。
